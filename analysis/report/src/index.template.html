02  目录结构与定位映射

相同的编号骨架，不同的血肉

两仓都采用「数字前缀分层」的样例骨架，但 cuda 是扁平陈列（类目/样例，两层到底），cann 是深层嵌套（类目/story/recipes｜tutorials/example/step，最深达 6 层）。cann 的 2_Performance 与 cuda 的 4_CUDA_Libraries + 5_Domain_Specific 承担了各自的重心，而彼此几乎不重叠。

04  产品定位 · 开源开放定位

「真开源」与「源码可得」之间

这是全对比中最具决策分量的一节。cuda-samples 采用 BSD-3-Clause——OSI 认证、任意用途、可商用可分发；cann-samples 采用 CANN Open Software License Agreement v2.0——限定用途（仅可为「华为 AI 处理器」开发/分发）、可撤销、含专利反制终止条款，不是 OSI 认证的开源许可。二者「开放」的含义并不相同。

cuda 定位

面向所有 CUDA 开发者的工具链特性陈列 —— 「展示 CUDA Toolkit 能做什么」。广、浅、可运行、可自由取用。

cann 定位

面向昇腾算子工程师的实战调优知识库 —— 「教你把某个算子在昇腾上打到极致」。窄、深、重文档、限昇腾用途。

许可条款关键差异：BSD-3 只要求「保留版权声明、不得以 NVIDIA 名义背书」，此外无任何用途或硬件限制，授权永久不可撤销。CANN OSL v2.0 的授权则明确写道：许可仅用于「开发专用于搭载华为 AI 处理器系统的软件」，且华为可在你违约或发起专利诉讼时随时终止授权、要求你删除软件及衍生作品。因此在「可自由分发 / 可用于非昇腾平台 / 长期法律确定性」上，cuda-samples 明显更开放。
05  给开发者的 samples

一个是「样例库」，一个是「教科书」

同样叫 samples，开发体验却不同。cuda 每个样例是一段聚焦的可运行程序 + 精简 README + 跨平台 CMake + 自动化回归；cann 每个 story 是一部逐步教程：从 0_naive 基准一路优化到 7_fullload，配性能建模文档、profiling 截图与数据校验脚本。

cann：递进式「story / recipe」

  • 📈 逐步教程：matmul_tutorials 0_naive→1_pingpong→2_block_swat→…→7_fullload，每步一个优化点
  • 🧩 多配方 recipe：同一算子的 MXFP4/MXFP8/HiF8/INT8 多量化实现并列
  • 📚 重文档：67 个 README/.md + 210 张图/图示，含性能建模与访存分析
  • 🛠 构建门槛高：cmake -DNPU_ARCH=dav-3510/2201 + ops-tensor 子模块 + 指定 Toolkit 版本
  • 🧪 Python 仅作数据生成/精度校验脚本，非可运行样例
  • 🔒 硬件门槛：需 Ascend 910B/C 或 950 真机，特性样例挑架构

cuda：聚焦式「一样例一特性」

  • 🎯 单点可运行：一个样例演示一个 API/特性，读完即跑
  • 🔁 NVRTC 变体：多样例提供运行时编译版（*_nvrtc）
  • ⚙️ 跨平台 CMake：Linux / Windows / Tegra 交叉 / DriveOS 一套构建
  • ✅ 自动化回归：run_tests.py + test_args.json 逐样例参数化跑测
  • 🐍 真 Python 样例：cuda-python + PyTorch/TF 自定义算子互操作
  • 🟢 硬件门槛低：任意 NVIDIA GPU 即可，README 精简
文档密度是最直观的分野：两仓 README 总量相近（各约 585 KB），但 cuda 摊在 258 篇里、单篇均值仅 ~2.3 KB（模板式卡片）；cann 集中在 67 篇里、单篇均值 ~10.6 KB（长文教程），单篇最大 64 KB。cann README 含约 7.6 万汉字与 184 张 tiling/流水/profiling 图；simd_vf_story 单篇 README 达 1644 行、matmul_story 1180 行并配 8 级递进教程。cuda 侧几乎无图，靠精炼英文小节 + 外链 SM 兼容矩阵。

      06  开源开放生态 · 治理与维护

      全球 PR 社区 vs 结构化 SIG 门禁

      两仓代表两种开源运营范式。cuda 是 GitHub 原生：任何人 fork + PR，pre-commit.ci 自动格式化，随 CUDA Toolkit 版本发布，历经 10.x→13.3 多年沉淀。cann 主场在 GitCode：SIG ops-basic 治理，Committer/Maintainer 分级评审，620 行 CONTRIBUTING 规范 story 模板，真机 CI 功能门禁；GitHub 侧只是同步镜像。

      07  选型建议

      什么时候选哪一个

      二者不是替代关系，而是服务于不同目标与不同硬件栈。用你在第 01 节调好的旋钮回看契合度，再对照下面的场景清单。

      选 cann-samples 当你…

      攻昇腾算子深度

      • 在 Ascend 910B/C 或 950 上做高性能算子开发/调优
      • 需要 LLM 推理算子（MoE、Fused Attention、RoPE+RMSNorm KV Cache）的工程实现范式
      • 需要 MX/HiF8/INT8 低比特量化矩阵乘的完整 recipe
      • 想系统学习「访存/指令/系统」三层逐步优化方法论
      • 接受限昇腾用途的许可与真机门槛，看重中文深度文档
      选 cuda-samples 当你…

      学 CUDA 生态广度

      • 要系统入门/概览 CUDA 全栈能力与 API 特性
      • 需要 cuBLAS/cuFFT/cuSOLVER/NPP/CUB/Thrust 等库的可运行示例
      • 做图形互操作（D3D/Vulkan/GL）或经典 HPC/金融计算
      • 关心开源合规、可商用、可分发与跨平台（Windows/Tegra/DriveOS）
      • 想要低硬件门槛（任意 NVIDIA GPU）与全球社区支持
